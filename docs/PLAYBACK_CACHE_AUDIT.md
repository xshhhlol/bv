# 播放磁盘缓存与调试图层检查

本次检查覆盖 ExoPlayer 的磁盘初始化、预下载、播放读取、快进快退、换视频/清晰度、退出清理、备用线路，以及调试图层的数据来源、刷新和焦点。

## 已修正的问题

| 问题 | 修正 |
| --- | --- |
| 播放连接持有长范围缓存写锁，后台下载可能拿不到写锁，下载的数据没有落盘 | 播放端只读缓存；每条流由独立后台任务写入，每块最多 2 MiB |
| 从播放器读取位置向前跳过固定 16 MiB，形成空洞，短音频可能一直无法预下载 | 从读取位置之后的第一处空洞开始补齐 |
| 旧任务取消与新任务启动交错；清理超时后旧任务仍可能写回文件 | 每个任务独立取消状态；等待写入实际退出后清理，每次播放使用独立缓存标识 |
| 仅用 URL 路径作为缓存标识，不同文件可能互相命中 | 播放会话隔离，仅同一条流的备用 CDN 共用标识；通用 URL 标识包含主机和查询参数 |
| 缓存初始化和索引访问可能阻塞主线程；构造成功不代表初始化成功 | 后台初始化并检查结果，发布缓存前清理旧文件；不可用时播放回退到网络 |
| 固定缓存窗口与低磁盘配额不匹配 | 根据剩余空间计算实际配额，所有流的窗口总和不超过配额的一半 |
| 每个短下载请求重置慢线路检测，难以累计到检测窗口 | 同一条流按 CDN 共享读取样本，跨请求保留待切换状态 |
| 调试图层把离散缓存量和文件字节占比换算成“前方可播秒数” | 分别展示读取位置之后的连续字节数、窗口内缓存量，不估算 VBR 缓存秒数 |
| 图层读取磁盘索引锁可能影响遥控操作 | 图层只读取后台发布的缓存快照 |
| 网速使用系统日期、关闭后旧采样可能残留 | 使用单调时钟和同步开关，展示近 5 秒网络接收平均值，包含预下载，不计磁盘读取 |
| 44.1 kHz 显示成 44 kHz；暂停/缓冲/倍速可能误报解码不足 | 保留采样率小数；渲染统计重置采样，区分播放状态，并按倍速展示期望帧率 |
| 换视频、切清晰度、开关图层可能保留旧调试文字 | 切换数据来源立即使旧快照失效；覆盖安装后尊重已保存的显示开关 |
| 长线路/编码器名称可能挤出画面 | 限制图层宽高并自适应字号；图层不参与遥控器焦点，菜单和弹窗在其上方 |

## 当前策略及数据含义

- 内存负责短期解码采样队列，目标上限为 30 秒，同时受按堆大小计算的 16–128 MiB 字节阈值约束。这里的采样内存不等于应用总内存，解码器、画面和其他组件另有占用。
- 磁盘配额最多 1 GiB，并且不超过初始化时可用空间的四分之一；可用空间不足 256 MiB 时关闭预下载。每条流窗口最多 256 MiB。
- 起播或重新缓冲时先供给播放器；播放器停止加载且已就绪后再填充磁盘窗口。暂停且缓冲已就绪时仍可继续预下载。
- “读取前方”以播放器的数据读取位置为起点，该位置通常已经领先于画面播放时间。音视频分别统计，不能把两者相加理解为可播时长。
- “缓冲终点”是该时间点在全片中的百分比，不是内存使用率；“磁盘缓存”是缓存目录内的媒体数据字节数，不含索引和文件系统额外开销。
- “最近线路”是最近选中的线路；已有的并发连接不一定同时切换。网速为实际接收量的滑动平均，填满缓存停止下载后降为零是正常现象。
- 换视频和退出播放后异步清理本次缓存；异常退出/覆盖安装留下的缓存，在下一次磁盘缓存初始化时清理。无需清空登录和应用设置。

## 验证

最终检查结果：13 项相关单元测试、15 项 Android 测试全部通过；播放器模块 Lint 无错误（2 条提示）；`assembleDefaultDebug` 构建成功。Android 测试环境为 API 36.1 模拟器。

- 单元测试：缓冲策略、磁盘预算、慢线路判断、网速采样、渲染采样和音频采样率。
- Android 集成测试使用真实 `SimpleCache` 和可控数据源：播放连接打开时后台落盘、缓存命中不重复联网、短音频无跳过空洞、跳转后补齐新位置、延迟退出的旧任务清理、标识隔离、磁盘淘汰、调试读取不等待缓存锁。
- CDN 测试：低速切换、备用线路失败时保留旧连接、断线/提前 EOF 后按准确偏移续传、后续请求使用成功的备用地址、短分块跨请求累计低速样本。
- Compose 测试：960×540 dp 和 320×240 dp 下长调试文本不溢出；显示图层前后播放控制保持焦点。

可复跑的检查命令（需要已启动的 Android 模拟器或测试设备）：

```sh
./gradlew :bv-player:testDebugUnitTest :bv-player:connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.class=dev.aaa1115910.bv.player.DiskPrefetchTest,dev.aaa1115910.bv.player.FallbackUrlDataSourceTest,dev.aaa1115910.bv.player.PlayerDebugOverlayTest \
  :app:assembleDefaultDebug
```

正式包还需单独执行 `./build.sh --offline`。补查发现，原先 Debug 的工具依赖间接引入了 Foundation 1.8.2，但 Release 仅解析到 1.7.6，导致新增图层的 `TextAutoSize` 编译失败。现在播放器模块显式声明与项目 Compose 版本一致的 Foundation 依赖，避免构建类型改变可用 API。

补齐依赖后，`./build.sh --offline` 已完整通过，包括 Release 编译、R8 混淆、APK 打包及签名校验。

这些测试确认缓存机制和统计行为，不替代实际电视上的长时间 4K 播放。实际 CDN 限速、电视磁盘吞吐和硬件解码稳定性仍需用原先卡顿的视频持续播放观察。
